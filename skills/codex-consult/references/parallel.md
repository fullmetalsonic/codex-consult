# 병렬 처리 (겹치지 않는 일은 동시에)

서로 독립인 주제·작업은 Codex 호출을 동시에 띄운다. 순서대로 할 이유가 없으면 병렬이 기본이다.

## 독립 판정 (모두 만족해야 병렬)

- 수정하는 파일·폴더가 겹치지 않는다(읽기만 하는 공통 파일은 괜찮음).
- 한쪽 결과가 다른 쪽의 입력·결정 전제가 아니다(순서 의존 없음).
- 같은 공유 자원을 쓰지 않는다: 같은 빌드 출력 폴더·포트·DB·실기기(폰·차량)·브라우저 프로필·로그인 세션, 전역 설치(npm -g, pip 전역 등).
- 하나라도 애매하면 순서대로 한다.

## 어떻게 나누나

- **협의(①②④)**: 과제가 서로 독립인 하위 주제로 나뉘면 주제마다 따로 패키지를 만들고 Codex 의견·검토 호출을 동시에 띄운다. Claude도 주제마다 따로 의견·검토를 쓴다. 공정성 규칙(같은 패키지, 상대 의견 보기 전 각자 작성)과 교환 생략 규칙은 주제마다 따로 적용한다.
- **실행(③)**: 합의된 실행 계획을 **작업 단위(트랙)**로 나눈다. 트랙마다 `round<N>-exec-plan-<트랙>.md`에 목표·**소유 파일/폴더 목록**·완료 기준을 적고, "소유 목록 밖 파일은 수정하지 말고, 필요하면 멈추고 보고하라"를 넣는다. 트랙마다 모델을 따로 고른다(코딩 트랙은 Terra).
- **검토(④)**: 트랙별 검토를 동시에 띄운 뒤, 마지막에 트랙을 합친 결과에 대한 **통합 검토 1회**(Sol 6.2)를 한다. 트랙 간 인터페이스·충돌은 통합 검토에서 본다. 트랙별 Codex 검토 모델은 트랙 성격으로 고른다(주고받기·토큰 절약 목적):

  | 트랙 | Codex 트랙 검토 |
  |---|---|
  | Terra가 짠 코드·시험 코드 | Sol 6.2 (작성 모델과 다른 모델이 검토) |
  | 정해진 기준의 대조·집계·문서 정리 | Terra (`-m gpt-6.1-terra -c model_reasoning_effort=xhigh`) |
  | 단순 추출·형식 확인 | Codex 검토 생략, Claude 검토만 |

  Claude 트랙 검토는 모든 트랙에서 그대로 한다. 같은 트랙 안에서는 검토 등급을 섞지 않는다. 변경분 검토·완료 전 전체 검토 규칙(본문 ④)은 통합 검토 기준으로 적용한다.

## 충돌 방지

- git 저장소에서 두 트랙 이상이 파일을 수정하면 트랙마다 `git worktree add <기록폴더>/wt-<트랙> -b cc/<트랙>`으로 분리한 작업 폴더에서 실행하고, 끝나면 Claude가 차례로 병합한다. 병합 충돌은 자동 해결하지 않고 다음 라운드 문제로 장부에 올린다.
- git이 아니면 소유 목록이 겹치지 않을 때만 같은 폴더에서 병렬 실행한다.
- 파일 이름: 트랙·주제마다 `-<트랙>` 접미사로 프롬프트·결과(`-o`)·로그·세션 번호 파일을 따로 둔다(`exec-session-id-<트랙>.txt`).

## 동시 실행 수

Codex 호출은 동시에 최대 4개. 그중 빌드·전체 시험처럼 PC 부하가 큰 실행은 2개까지. 공유 자원을 쓰는 실행은 1개.

## 기다리기·실패

모두 백그라운드로 띄우고 완료 알림을 기다린다(폴링 금지). 한 트랙이 실패해도 다른 트랙은 계속하고, 실패 트랙만 본문 ③의 실패 처리를 따른다. 진행 알림에는 트랙별 상태를 한 줄씩 적는다.
